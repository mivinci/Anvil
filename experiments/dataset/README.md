# 数据约定草案

采用 JSONL 记录候选动作，每行对应一次决策中的一个候选。生成器已实现，训练加载校验待实现。当前特征版本为 1，JSONL 使用相对坐标、局部网格和历史摘要。

| 字段 | 内容 |
| --- | --- |
| schema_version | 数据格式版本 |
| scenario_id / map_id | 场景和地图身份 |
| episode_id / decision_id | 完整轨迹与当前决策身份 |
| tick | 观察采样时刻 |
| task | 任务类型与目标参数 |
| candidate_id | 当前决策内唯一的候选 ID |
| action | 动作类型与参数 |
| valid | 当前观察下是否可执行 |
| features | 固定特征版本对应的数值或类别字段 |
| relevance | 候选评分，分值越大越好 |
| label_source | 专家、分支模拟或真实执行结果 |
| executed | 此轨迹实际执行的候选 |
| rollout_return | 固定后续策略下的模拟分支累计回报 |
| outcome | 已验证的执行结果，未知时为空 |

训练分组使用 `episode_id + decision_id`，不能将不同观察中的候选混为一组。候选 ID 不作为特征，避免学习候选排列。无效候选在选择时屏蔽，训练时排除。

特征需要包含任务、自身与目标相对状态、环境摘要、候选动作属性和近期历史。未知状态显式表示，防止与安全或空闲状态混淆。

模拟候选评分在相同状态、相同外部随机扰动和相同后续策略下比较，记录 rollout 时长、奖励配置、种子及后续策略版本。评分依赖后续策略，不视为动作的普适价值。

真实轨迹只记录实际执行动作的结果。未执行候选的结果保持未知，不能据此直接标成失败。划分数据时按完整地图与 episode 隔离，预处理参数只从训练集拟合。
