## 第三项补充：暂停与继续

- q2q-http 固定 revision 提供 `Task::cancel` 与 `Downloader::resume`，没有原位暂停 API。Runtime 用独立的传输取消令牌停止本轮下载，等待 Core 回收全部工作任务后才进入 `paused`；保留同一逻辑任务、原安装计划与 q2q-http 分片/恢复文件，不将任务标为 cancelled，也不新建安装 ID。
- 继续时唤醒原任务，重新校验已完成缓存，并由 q2q-http 恢复可用分片；文件进度会重新统计，不承诺完全不回退。暂停期间没有下载请求和定时轮询，后台等待显式继续或取消。
- 新增 `POST /operations/{id}/pause` 与 `/resume`；状态扩展 `pausing/paused/resuming`。仅下载阶段可申请暂停，解析/保存阶段不可暂停；暂停/继续与最终结果存在竞态时，以实际返回快照为准，不能将已经提交的成功结果覆盖为暂停。
- 暂停也占用单安装任务位置，不被历史清理淘汰。取消暂停任务、退出应用会唤醒并结束它；继续前不需重新选择版本或名称。任务只在当前 Runtime 生命周期内保留，未实现跨重启的暂停任务记录。
- 前端以 Runtime 确认的状态展示“暂停中”“已暂停”“继续中”，稳定暂停时停止查询；取消暂停任务后继续查询到终态。关闭面板只收起，不隐式继续下载。

检查：前端静态检查、Runtime 离线编译与 release 构建、Rust 格式检查通过。未运行测试或发起真实游戏下载；真实暂停后的网络停止、分片恢复、取消及发布竞态仍需维护者手动验收。新增 API 需要完整重启 dev 后使用。

## 下载字节与速度

Core 从 q2q-http 的 `staged_bytes`、`received_bytes` 聚合下载进度；活跃文件记录按并发上限受限，完成后移除。总大小按去重资源计划求和，已完成缓存与可恢复分片计入可用字节；网络接收字节独立累计，不将缓存重验计成网络下载。中间字节进度最多每 100ms 发布，文件结束强制发布最终值。

Runtime 快照新增 `downloadedBytes/totalBytes/receivedBytes`。前端按相邻实际快照的网络接收字节差和单调时钟间隔计算速度，不额外引入轮询。首个样本显示占位，静止传输显示 0；暂停/继续重新取样，查询失败隐藏旧速度。下载阶段显示“当前大小 / 总大小 · 速度”，解析、校验、保存、暂停、取消与终态不显示速度。

检查：Core、Runtime 与 CLI 离线编译，前端静态检查和 Rust 格式检查通过；Runtime release 构建更新到开发包。未运行测试或触发真实下载，速度与缓存/断点行为仍待维护者真实操作验收。新增字段需完整重启 dev 生效。

## 版本目录缓存

按已确认方案增加两层缓存：窗口级 ClientVersionState 跨安装弹窗复用数据和在途读取；Runtime VersionCatalog 保留一份通过 Core 官方校验的原始目录，成功获取后有效期 30 分钟。前端使用 Runtime 返回的剩余有效期，不再额外叠加 30 分钟。两层均只在首次读取、过期后打开或手动刷新时工作，无定时轮询。现已补充下方磁盘快照，Runtime 重启按原始获取时间恢复，前端窗口缓存仍随页面生命周期清空。

首次无缓存等待有界读取；Runtime 过期缓存立即返回并启动后台更新，前端先显示旧数据，再等待同一更新结果。刷新操作并发合并；更新批次号避免后台已经完成（包括失败）时前端补取又触发重复下载。单次 Runtime 获取 30 秒超时，前端 HTTP 35 秒超时。关闭弹窗不取消窗口级读取，Provider 销毁中止前端请求；Runtime 共享更新最长继续 30 秒，进程退出结束，不绑定某一个 HTTP 请求的取消。

安装面板搜索旁增加手动刷新按钮与更新指示；刷新时保留列表、选择和用户编辑的实例名，搜索/正式版/快照切换继续本地处理。已有缓存时刷新失败显示小提示并仍可安装；首次获取失败显示整块错误和重试。成功列表为空与获取失败区分。

新增受现有鉴权保护的 GET /client/version-catalog，返回 versions、stale、freshForMs、revision 和 refreshError；refresh=true 强制更新，after 仅用于过期结果的后续等待。原 GET /client/versions 数组响应保持兼容，内部同样使用 Runtime 缓存。安装计划仍由 Core 解析和验证，不以缓存目录替代安装校验。

## 实例直接启动

## 同版本实例缓存复用与进度核对

## 首页官方新闻 RSS

首页按需读取 Minecraft 官网 `community-content/rss`，Runtime 在服务端解析并校验 Feed，只向前端返回标题、日期、分类和 HTTPS 原文链接，不嵌入文章正文或外部图片。磁盘仅保留单个最多 256 KiB 的快照，有效期 6 小时；首次读取后不轮询，过期先呈现缓存并后台更新，刷新失败保留旧内容，页面按钮可手动刷新。首页优先显示带 Java 分类的最新三条；Feed 没有 Java 分类时回退显示最新三条官方动态。文章由 Shell 在系统浏览器打开。

检查：`cargo check --locked --offline -p anvil -p anvil-core` 与 `npm run check --workspace @anvil/desktop` 通过。`cargo fmt --all -- --check` 在此 Windows 执行环境中因 Rustfmt canonicalize workspace path 返回“拒绝访问”而未能运行。首次尝试直接请求 RSS 时，本机 DNS 无法解析 `www.minecraft.net`；之后用当前 User-Agent 读取到 HTTP 200。Runtime/WebView 仍需完整重启后进行真实读取 smoke。

2026-10-24 排查：官方响应为 `application/rss+xml; charset=utf-16`，BOM-less UTF-16LE；文章链接使用 Atom 命名空间的 `a10:link` 元素及 `href` 属性，而非普通文本 `<link>`。同一 `Anvil desktop news reader` User-Agent 请求返回 HTTP 200，因此此前 502 的原因是 Feed 解码/字段映射不兼容，不是 User-Agent。Core 现按 BOM/XML 前缀解码 UTF-16LE/BE，并同时读取 Atom `href` 与 RSS 文本链接。修改后 `cargo check --locked --offline -p anvil -p anvil-core` 通过；完整 Runtime/WebView 读取尚待重启验收。

后续由 Hono + Zod / Cloudflare Workers 定时同步官方 RSS、补充文章封面并提供丰富 Feed 的计划见[新闻服务执行项](news-service.md)；该服务目前尚未创建或部署。
