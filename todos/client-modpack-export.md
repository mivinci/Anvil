# 实例导出整合包

状态：第 1–4 项已在本地接入，当前可从实例概览发起导出并由窗口级任务面板跟踪；第 5 项往返/原生 WebView/真实游戏验收未做。导入进度见[整合包导入](client-modpacks.md)，Q2Q 的 URL policy 已合入；Anvil 改动仍按维护者要求保持本地未提交。

## 产品流程

实例概览的“启动”右侧增加次级“导出”。点击打开轻量面板：整合包名称、包版本，以及模组、资源包、光影、配置和存档选项。默认选前四项，存档默认不选。包名默认实例名称；包版本优先使用已记录的原整合包版本，否则默认 `1.0.0`，与 Anvil/Minecraft 版本无关。

确认后由 Runtime 创建窗口无关的后台导出任务，现有全局任务面板显示收集、打包、校验、完成/取消/失败。关闭面板或切换页面不停止；运行或准备启动中的实例禁止导出，后端必须使用同一实例锁保证导出与启动、资源修改、删除互斥。按钮禁用不能代替服务端校验。

首期保存到系统下载目录，使用名称/版本生成 `.mrpack` 文件名；同名追加序号，不覆盖已有文件，任务结果显示保存位置。下载目录不可用时明确报错。Runtime 决定保存目录，页面不能传任意写入路径；Shell 不增加整合包业务命令。可选目录选择作为后续体验扩展，不混入首期。

## 内容与格式

- 只支持已有原版/Fabric 实例，从有效安装记录写入 Minecraft 与 Fabric Loader 版本；不推断 Java 安装位置或导出游戏本体。
- 使用 Modrinth formatVersion 1，根 `modrinth.index.json`，选中文件全部写入 `overrides/`；`files` 为空，不依赖平台下载链接，也不猜测本地 JAR 的在线来源。生成完成后必须能通过现有 `inspect_archive` 重新解析。
- 默认导出实例实际使用的模组、资源包、光影和配置，资源按当前独立运行副本收集。停用且未物化的资源不偷偷启用，不导出整个共享仓库。
- 配置首期覆盖 `config/`、`defaultconfigs/`、`kubejs/`、`scripts/` 及明确列出的游戏设置文件；其它目录不当成完整实例备份复制。存档只有显式选中时包含 `saves/`。
- 不包含 Anvil 账户、令牌、Java、游戏缓存、日志、崩溃报告或截图。拒绝链接、特殊文件、越界、重复/大小写和文件/目录冲突；资源与输入变化需检查，不能混合不同时刻的快照。
- 数量、路径深度、单文件、解压总量、压缩包总量须与现有导入器兼容；超过限制在发布导出结果前失败，不能生成 Anvil 自己无法导入的包。先写私有暂存包，校验后再发布；取消/失败清理本次临时产物，不改动源实例和已存在输出文件。

格式依据：[Modrinth .mrpack 规范](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。

## 执行项

每项完成后汇报当前范围；保持一个最终 Anvil PR，不分阶段提交，维护者测试期间不提交或推送。

1. [x] **导出选项与格式契约**：Core 选项类型、默认选择、名称/包版本校验，基于安装记录生成可被现有解析器接受的 index；明确自包含包与内容边界。
2. [x] **Core 快照与打包**：实例/设置锁、有界文件收集、运行状态互斥、资源副本/配置/可选存档、取消、变化检测、ZIP 写入及重新解析验证、暂存结果原子发布；离线临时实例测试。
3. [x] **Runtime 导出任务**：鉴权、幂等、并发/历史/临时文件预算，进度与取消，系统下载目录及无覆盖保存，退出时清理；结果不与安装回执混淆。
4. [x] **桌面按钮、面板与全局任务**：启动旁次级按钮、运行时禁用、选项默认值、提交/未知结果恢复、离页继续、完成位置提示及错误/重试。
5. [ ] **往返与界面验收**：导出→重新导入的离线文件/加载器/资源验证、存档开关、修改/锁/取消/容量边界、浅深色与真实 WebView；维护者验收实际游戏后再宣称支持范围。

## 第一项当前实现

Core `modpack` 提供 `ExportSelection`、`ExportOptions`、`ExportIndex` 和 `prepare_export_index`。选项默认包含模组/资源包/光影/配置、排除存档，拒绝空选择、无效名称/包版本与未知请求字段。index 只从有效安装记录读取 Minecraft/Fabric 版本，不包含安装路径、Java 或下载凭据；自包含格式使用空 files，实际文件写入 overrides 留待第 2 项。

3 项离线测试通过：默认选项与请求字段边界、原版/Fabric 元数据经现有导入解析器往返、无效输入及安装快照拒绝。`cargo fmt --all -- --check`、Core lib clippy 与 diff 检查通过。尚未生成真实 ZIP、增加 Runtime 导出 API、界面按钮或保存文件；未提交/推送。

## 第二项当前实现

Core 新增 `ModpackExporter::export`、导出阶段/进度和结果类型，接收调用方确定的目标 `.mrpack` 路径；尚未提供 Runtime API 或界面入口。

- 在同一实例锁与设置锁内读取安装记录和资源布局，拒绝未同步/未完成资源事务、缺失或已修改的受管副本；不调用资源修复、不修改源实例。Core 锁覆盖游戏持锁期间，Runtime 的准备启动状态判断留待第 3 项。
- 按选项收集实际 game 文件，包含明确配置目录及 options 设置文件，存档显式选中才读取。跳过日志/缓存/仓库元数据目录及已知账户凭据文件；不扫描整个实例或共享仓库。文件内容/元数据和所选目录树在打包前、写入中、验证后核对，发现变化停止，不宣称对任意外部编辑提供文件系统级快照。
- 有界遍历、读取及压缩，沿用导入的路径/数量/单文件/总量限制；直接受管资源继续限定 64 MiB，并调用同一 JAR/资源包/光影校验。压缩写入硬限 512 MiB，完成后用 `inspect_archive` 和安装资源边界重新验证。
- 使用目标目录中的私有临时文件，校验成功才无覆盖发布；拒绝保存在源实例中。取消/失败删除本次临时文件，发布是完成提交点，不因随后取消而将已保存结果误报为取消。

8 项新增导出 fixture 通过：自包含包的原版/Fabric 契约接续与所选文件重解析、模组/资源包/光影及配置、存档开关、已有输出保护、源目录输出拒绝、实例/设置锁互斥、源变化/未完成事务、资源被修改时只读拒绝、非法内容/容量/链接/大小写冲突、打包中取消及清理。Core all-targets clippy、Rust 格式和 diff 检查通过。测试仅使用临时实例及内存数据，未导出维护者真实实例、未启动游戏、未提交/推送。


## 第三、四项当前实现

- Runtime 新增独立 `ModpackExports` 任务管理器：`POST /clients/{name}/modpack-exports` 创建，`GET /modpack-exports` 列表，`GET/DELETE /modpack-exports/{id}` 查询/取消。请求 UUID 幂等，同一请求绑定不同实例或选项返回冲突；同时只允许一个导出任务，保留最近 8 项。
- 输出目录使用系统 Downloads；名称/版本生成 `.mrpack`，同名追加序号，不覆盖已有文件；Core 仍负责实例/设置锁、有界快照、ZIP 校验和原子发布。
- 进度阶段为收集、打包、校验、保存、完成；任务可取消，Runtime 退出时取消并等待；返回值包含保存路径、大小、SHA-256 和文件数，和安装回执分离。
- Desktop 在实例概览启动旁增加次级“导出”；面板默认整合包名称为实例名、版本优先取 `modpack.json` 的原包版本（否则 `1.0.0`），默认选中模组/资源包/光影/配置，存档不选；提交后进入现有下载任务面板，离页继续，支持取消、未知结果恢复和重新导出。
- 验证：Runtime 导出任务临时实例测试通过（实际生成、重新校验、同名不覆盖）；前端状态 3 项测试通过；`svelte-check`、生产构建和 Rust 全量测试/Clippy 通过。尚未在原生 WebView 操作、导出维护者真实实例或完成导出→重新导入验收。
