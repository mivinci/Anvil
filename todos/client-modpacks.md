# 整合包导入

状态：格式/ZIP、Core 安装、Runtime 全局任务及桌面入口已在本地接入，等待维护者真实包验收。Q2Q 的重定向 URL policy 已合入（PR #97，提交 `a9bc58f0`）；Anvil 改动仍未提交、未推送，不代表已发布功能。

## 产品流程

客户端列表在“安装版本”左侧增加次级“导入”按钮，首期选择本地 `.mrpack`。选择后提交一个窗口级全局任务并提示“正在解析整合包…”，解析也属于该任务；全局下载面板随即显示，切换页面不停止。解析成功自动准备环境、下载文件、应用配置并发布新实例，不增加安装确认弹窗。失败说明原因，支持取消和显式重试。

实例默认使用包名，冲突自动追加序号；名称预留需由 Runtime/Core 统一处理，不能靠前端列表推断。完成前不进入正常可启动列表；失败不影响已有实例或共享缓存。Runtime 重启后的恢复边界另在任务实现时明确，不将窗口内重试写成跨进程恢复。

## 首期范围与规则

- Modrinth formatVersion 1、Minecraft、原版或 Fabric；拒绝 Forge/NeoForge/Quilt 和未知依赖，不猜测兼容。在线搜索、其他格式和整合包版本升级不在导入首期；后续确认的导出另见[实例导出整合包](client-modpack-export.md)。
- 无 env 时视为客户端必需；client=unsupported 跳过，optional 默认包含。解析仍检查全部文件，不能借服务端标记绕过路径和来源校验。
- 要求 SHA-1/SHA-512、文件大小与 HTTPS 镜像地址；复用 q2q-http，安装必须验证内容身份。首期下载来源限制为官方格式所列 Modrinth CDN、GitHub、raw GitHub、GitLab；重定向也须受控，具体下载适配在第 3 项完成。
- paths 必须为跨平台可用的相对路径；拒绝越界、链接、重复/大小写冲突、文件与父目录冲突。ZIP entries、index、解压总量和单文件均设上限。
- overrides 后应用 client-overrides，忽略 server-overrides；层间同路径允许明确覆盖，层内重复和跨层文件/目录冲突拒绝。只写新实例 game 目录，不写安装器记录或执行脚本。
- mod/资源包/光影尽量引用共享对象，普通 config/options 等可变文件保留实例独立副本；不把整合包当成一个 mod，不擅自安装清单外依赖。
- Core 持有解析、安装计划与事务；Runtime 持有上传、鉴权、幂等任务、名称预留和生命周期；Desktop 接选择文件、提示和全局任务；Shell 不增加领域逻辑。

格式依据：[Modrinth 官方 .mrpack 规范](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。

## 执行项

每项完成后汇报并确认下一项。

1. [x] **格式契约与安装计划**：Core index 类型与校验，明确版本/加载器、环境过滤、哈希/URL/路径、重复与容量边界，离线 fixture 验证。
2. [x] **有界 ZIP 解析**：读取根 index，检查所有 entry、大小/数量、符号链接、override 层级和冲突，取消时停止；产出可安装计划，不写实例。
3. [x] **Core 安装与原子发布**：复用 Java/游戏/Fabric、q2q-http 和共享仓库，校验文件并应用 overrides，保留来源版本，名称预留与成功发布，失败/取消清理和重试。
4. [x] **Runtime 全局导入任务**：有界文件上传、任务先于解析创建、解析/准备/下载/应用/完成阶段、状态查询/取消/重试、幂等和并发边界；任务继续运行不依赖页面。
5. [x] **桌面入口与任务面板**：次级导入按钮、文件选择、非阻塞解析提示、同一全局任务的进度与重试，成功刷新实例。
6. [ ] **验收与状态文档**：离线端到端/异常路径、浅深色及离页接续；真实包下载/游戏启动由维护者验收，明确平台范围。

## 第二项实现与验证

Core 提供阻塞、可取消的 `inspect_archive`，返回 index 计划、客户端有效 override 的原 entry 索引/路径/大小，以及原包 SHA-256。调用方应在 blocking pool 中运行，后续安装必须使用同一不可变上传文件并复核摘要；目前不落地 override 或实例。

- 压缩包最多 512 MiB，ZIP entry 最多 20,000，单 entry 最多 128 MiB，声明解压总量最多 2 GiB，index 继续限制 8 MiB。读取 ZIP 前预检结束记录和中央目录，限制中央目录 16 MiB 并核对记录数量；首期明确拒绝 ZIP64、多卷和非标准目录扩展。
- 所有 entry（包含忽略的服务端文件）均检查路径、类型、大小和 CRC，拒绝链接/特殊文件、截断、层内重复、大小写及文件/目录冲突。读取和摘要计算按块检查取消。
- overrides 与 client-overrides 按层级合并，不依赖 ZIP 存储顺序；客户端同名覆盖通用文件。合并后与下载文件检查目录冲突，不安装 server-overrides。
- 11 项 Core modpack fixture 测试通过，新增覆盖覆盖层顺序、服务端跳过、缺失 index、非法路径、目录冲突、符号链接、内容损坏、取消和目录数量边界。Core lib clippy、Rust 格式及 diff 检查通过。

真实“海岛生存 1.0.0”包完整解析通过：11 份下载文件、28 份有效 override、17,610 字节，SHA-256 `6fe48bb3fc2b47786f08417c31ff790fe9219c7e11255c9c4be8a183de021abd`。没有联网下载、创建/启动实例或修改原包。临时检查程序已清理；Runtime/UI 尚未接入。

## 本地安装与界面状态

- Core 先复制/校验不可变输入、预留新实例名称，再准备 Java、原版/Fabric 和整合包文件。包中文名称可作为显示名称，生成兼容托管目录的 ID；已有 ASCII ID 保持不变，名称冲突追加序号。
- 下载复用 q2q-http 的连接池与预算；初始来源受白名单约束，重定向额外允许 GitHub 的 release-assets/objects CDN。验证文件大小、SHA-1/SHA-512 后进入共享 SHA-256 仓库；可变配置和运行副本独立，普通受管模组/资源包/光影接入现有清单与布局事务。首期每个受管文件沿用 64 MiB、受管资源合计 1024 个的限制，其他文件保留在实例 game 内。
- 实例全程位于隐藏 staging，完成配置和资源布局、安装/来源记录与目录同步后才原子发布。取消/失败清理本次 staging，已有实例不覆盖，已校验共享缓存保留。
- Runtime 先以请求 UUID 登记全局任务，再流式接收文件，不将整个包读入内存；重复请求绑定同一文件名/大小并返回原任务。上传限一个并发、512 MiB，未完成上传有超时边界；中断、取消、失败均转为任务终态。解析、安装与任务查询复用全局 installation 生命周期，退出 Runtime 会取消并等待结束。首期不提供整合包暂停。
- Desktop 在安装版本左侧提供次级导入按钮和文件选择，显示非阻塞读取/解析提示；同一任务进入现有下载面板，离页继续，完成刷新客户端。显式重试复用窗口内所选 File 但创建新的尝试；页面重载丢失 File 后需重新选择。网络结果未知先查询原请求，不盲目重复创建实例。
