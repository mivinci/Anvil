# 桌面首页玩家、快捷游玩与动态

状态：H1–H4 已实现（Core 统计存储、Runtime 会话采集与 API、首页玩家卡与统计接入）。2026-10-26 首页首版调整为常驻快捷游玩、Anvil 内置动态轮播及 Minecraft 官方动态；当前账户最近实例读取已有 Runtime 统计，离线模式可兼容本机最近记录。设置 → 账户已接入当前账户/本机全部游玩记录的确认清除。原生 WebView 视觉与真实交互待维护者验收；远端 Anvil 新闻源和皮肤全身展示仍未做。

## 目标与非目标

- 目标：首页先回答“我是谁、上次玩什么、现在玩什么”，再进入实例管理；玩家卡提供真实的身份和本地游玩统计，不靠装饰性文案制造个性。
- 目标：统计与账户绑定，切换账户后卡片展示该账户的数据；统计由 Runtime 记录，页面刷新或重开不影响归属。
- 非目标：不读取世界、截图、成就或游戏内统计数据；不做云同步、排行榜、遥测或跨设备统计。
- 玩家卡快捷游玩复用现有启动控件、账户登录和启动补装流程；前端不上传计时，账户设置仅能明确清除所选范围。

## 卡片内容

### 玩家卡

1. 身份：56px 皮肤头、用户名、账户切换箭头、`Microsoft 账户` 徽章；点击头像/用户名打开账户菜单。
2. 统计：登录后显示总游玩、近 7 天、启动次数、最常玩；未登录隐藏，不显示空 `—` 格。
3. 常驻快捷游玩：优先显示运行中的实例（多个时最近启动优先），其次是其他活动启动任务，再次是当前账户最近玩的有效实例；离线模式同时兼容已有本机最近记录。实例名进入详情，运行时显示日志，准备时支持取消，空闲时可直接启动。没有历史则选实例，没有实例则进入安装入口；删除实例后跳过无效历史。
4. 快捷启动复用 ClientLaunchControls 的紧凑按钮与反馈，保留缺少 Java、认证失败、文件冲突等显式处理；查询运行状态失败时先提供刷新，不重复启动。多个活动实例有数量和实例库入口。
5. 操作：实例库、刷新统计，贴底排列；账户管理走菜单。

### Anvil 动态轮播

- 替换旧的大幅最近游玩卡，使用独立的 `anvil-news` 内置编辑数据与 SVG 插画，展示三条已有功能的介绍，链接到实例库、模组和光影页面；不虚构新闻日期或版本。
- 8 秒自动切换，500ms 淡入淡出，提供圆点、前后按钮及暂停；悬停、焦点进入、页面隐藏或系统要求减少动态时停止自动切换。卸载时清理计时器与监听。
- 固定最小高度并与首行拉伸，切换不改变布局。内置内容不发网络请求；远端 Anvil Feed 尚未接入，与独立计划中的 Minecraft 丰富新闻服务区分。

### 其他区域

- 全部实例占满整行，沿用实例卡片网格。尚无实例时保留标题、浅色插画空状态和“安装版本”，直接打开现有安装步骤面板；已有安装任务时入口改为安装进度。加载与读取失败分别显示状态/重试，不能误显示成空库；发布成功后共用列表状态自动替换成真实实例。
- Minecraft/Java 官方动态保留首行右侧窄栏，最多显示八条，可在内部滚动，与 Anvil 自有内容分别维护；新闻内容不撑高首行。

## Runtime 采集

采集放在 `crates/anvil/src/serve/launches.rs` 的实际启动路径，不信任前端上报：

- 在 `run()` 调用 `phase(&updates, Phase::Running)` 的位置记录会话开始时间。
- `run()` 返回时（正常退出、失败、取消）记录结束时间；`duration = min(end - start, 24h)`。
- 持续时间小于 10 秒的会话不计时长，但仍计一次启动；避免误点启动污染统计。
- 未进入 running 就失败/取消的启动不计入启动次数。
- 账户归属取 `LaunchRequest.account_id`；离线测试使用 `offline` 桶，不计入 Microsoft 账户统计。
- 实例使用实例 ID（稳定），展示时由 UI 解析当前名称；实例已删除时显示“已删除实例”或隐藏该行。
- 同一 Runtime 最多 4 个并发启动，统计存储用互斥量串行写入；每次会话结束触发一次持久化，不做定时轮询。
- Runtime 正常关闭时，`shutdown()` 取消 active 启动并等待任务结束，`run()` 会记录到取消时刻；进程被强杀或断电会丢失当前这一局，这是明确边界。
- 时钟回拨或跨时区不改变已记录的 `durationMs`；总时长只累加 duration，不用起止时间反推。

## 存储

存储归 Runtime 数据目录，文件 `<data-dir>/play-stats.json`，schema 1，原子替换：

```json
{
  "schemaVersion": 1,
  "accounts": {
    "<account-uuid | offline>": {
      "totalMs": 0,
      "launches": 0,
      "lastPlayedAt": null,
      "lastInstanceId": null,
      "instances": {
        "<instance-id>": { "totalMs": 0, "launches": 0, "lastPlayedAt": 0 }
      },
      "sessions": [
        { "instanceId": "...", "startedAt": 0, "endedAt": 0, "durationMs": 0 }
      ]
    }
  }
}
```

- 数据模型、校验、裁剪和原子写入放在 `anvil-core` 的 `play_stats` 模块，复用现有有界读取和 `replace_json`；Runtime 负责启动生命周期和 HTTP，不把 UI 逻辑放进 Core。
- 有界：最多 32 个账户、每账户 64 个实例、每账户 256 条会话、全局 2048 条会话、单文件读取上限 512 KiB；写入前按 `lastPlayedAt` 裁剪旧会话。
- 会话列表用于“近 7 天”和最近游玩；超过上限时丢弃最旧明细。账户 totalMs/launches 独立持久化，不因裁剪 64 个实例的明细而倒退；旧 schema 1 文件缺少两字段时，从已有实例聚合补齐后在后续写入中保存。近 7 天仍按受限会话明细滚动计算。
- 读取失败或 schema 不符：保留原文件并复制为 `play-stats.corrupt.json`（只保留一份），本次以空数据启动，记录 warn；不静默删除用户数据。
- 实例删除成功后保留所有账户的累计值与历史会话；最常玩命中已删除实例时显示“已删除实例”，快捷启动仅选择现存实例。退出账户也保留统计，重新登录同一 UUID 可以接上；被旧删除逻辑清掉且无备份的记录无法恢复。
- 不做文件锁以外的跨进程同步；同一数据目录只允许一个 Runtime。
- 不记录 token、邮箱或其他凭据；账户 UUID 是公开标识，不写入日志。

## Runtime API

- `GET /play-stats`：返回 schema 版本、所有账户的聚合值、最近 20 条会话；沿用 Origin/Bearer 鉴权，无缓存。
- `DELETE /play-stats`：明确清除本机所有账户和离线统计；成功确认后，桌面另清除本机 recent-plays 缓存，不删除实例、存档或登录账户。
- `DELETE /play-stats/accounts/{id}`：只清除指定账户，保留其他账户和 offline 桶；空/非法 ID 拒绝，不回退全量。采用独立路径，旧 Runtime 返回 404 时不能转调全量端点。
- 两种清除都由 Runtime 在 Launches 的准入锁内检查没有活动启动任务后原子持久化；准备/运行/停止阶段返回 409，结束后才可清除，防止新启动和旧会话结算竞争。
- 不提供前端写接口；统计只能由 Runtime 生命周期产生，避免伪造和重复计数。
- 返回体只含统计和公开 ID，不含路径、token 或凭据。
- `ClientLaunch` 快照的 `startedAt` 用于运行时长展示；实例删除结果的 `id` 只用于实例引用联动，不再清理历史统计。

## UI 接入

- `play-stats-state.svelte.ts`：首页挂载时读取一次；启动任务进入终态后、切换账户后显式刷新；不轮询。
- 读取失败只隐藏统计区，不影响身份、实例和启动；错误不阻塞主流程。
- 当前账户过滤对应账户的数据；`offline` 桶不混入 Microsoft 统计。
- 切换账户后立即切换统计和快捷游玩的最近实例；活动任务始终优先显示，下面实例列表保留全局本机最近排序。
- 账户未登录：身份区显示登录入口；统计区隐藏。
- 统计为空：显示“启动游戏后开始统计”，不显示 0。
- 实例删除后按列表解析历史名称，不删除统计；缺失的实例不会继续作为启动目标。
- 新增文案进国际化字典；日期、时长、相对时间用当前 locale 的 `Intl` 格式化。
- 无障碍：卡片用 landmark + 标题层级；运行状态 `aria-live="polite"`，分钟级更新，不逐秒刷新。

## 账户设置中的游玩记录

- 入口位于设置 → 账户；显示当前账户和游玩记录两行，当前账户清除为主要操作，本机全部清除为次要操作。两种范围都弹确认，账户 ID 和用户名在打开确认时捕获，避免异步账户切换误清对象。
- 尚未登录时禁用单账户清除；记录为空、初次读取失败或旧版本不支持时不允许无提示提交。游戏活动或运行状态未知时阻止清除并说明原因。
- 清除请求发出前使旧 GET 失效，防止旧响应覆盖新快照；成功采用返回快照，返回首页时按需重读。超时/响应丢失保留“结果未确认”，仅允许重新读取并核对，不自动重发 DELETE。
- 全量清除成功后同时删除本机最近游玩缓存，存储受限时明确报告缓存清理失败。单账户清除不动全局离线最近缓存。
