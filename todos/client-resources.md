# 客户端详情与共享资源设计

状态：详情页、本地资源共享/物化、Fabric 安装、Modrinth 与 CurseForge 浏览/受限依赖计划/共享下载及实例提交已实现；Modrinth 真实只读元数据与临时实例计划检查已通过，实际下载及游戏内加载仍待验收；完整依赖约束求解、资源暂停/恢复与跨实例在途传输消费者模型尚未实现，真实验收范围见各阶段记录。源于维护者确认的方向：每个客户端有独立详情页，可下载和管理其资源；相同 mod 共享下载，客户端保存引用。本设计细化该方向，链接默认策略、资源平台接入另在实施前确认。

## 现状与目标

- 当前 `/clients` 是实例列表，点击实例进入详情路由；已提供独立详情、本地模组管理及 Fabric 安装 API。Modrinth 与 CurseForge 浏览、确认安装与资源任务已接入，Modrinth 无需凭据；真实下载/运行验收待进行，CurseForge 另待 API Key 联调。
- Core 已按文件哈希复用原版游戏资源，实例 `installed.json` 引用共享缓存；沿用内容身份、校验、原子发布和 q2q-http 下载能力，不另写下载器。
- 实例目录、世界、配置、截图和日志相互隔离。相同游戏版本可创建多个不同实例，各自选择模组版本、启用状态和配置。
- 本设计优先 mod；资源包/光影复用文件仓库和引用模型，但安装位置、兼容判断各自定义。整合包是实例配置与资源集合，不视为一个普通 mod。

### 第一项：代码盘点与确认的设计

**第一项盘点时的实现基线（迁移进度以上方清单为准）**

- `/mods/+page.svelte` 只有页面标题，没有目录或项目详情；nav 已有该路由入口。
- `/clients/[name]/mods` 负责当前实例已安装资源的导入、启停和移除，通过 `ClientModBrowser` 弹窗承担搜索、来源切换、版本列表、计划和确认安装。
- Modrinth 和 CurseForge 浏览路由均位于 `/clients/{name}/{source}/...`，服务端从真实安装记录读取游戏版本，并拒绝非 Fabric 实例；不能直接用于未选择实例的全局发现页。
- Core/Runtime 已有 5 分钟有界浏览缓存和并发刷新合并；安装计划与实际文件下载独立。`ResourceInstallState` 及 Runtime 资源任务在窗口层持有，迁移页面不需要重建下载系统。

**页面与导航**

- `/mods` 为同一发现页；nav 进入时不默选目标实例，不因曾操作其他实例就隐式沿用安装目标。
- 实例入口跳转 `/mods?instance=<规范化实例名>`；来源可用 `source=modrinth|curseforge` 表示，默认 Modrinth。项目和搜索状态使用 `project`/`q` 查询参数，项目标识始终与来源绑定，前进后退可恢复浏览上下文。
- 模组页与实例页复用 PageSidebar 的宽度、背景、滚动及收起动画。来源、目标实例和实际兼容条件放入侧栏，侧栏顶部显示“模组”标题，实例选择位于来源切换上方，主内容保留搜索与项目浏览，移除标题说明小字；不额外展示“来源/安装到”文字标签。实例名称由顶部选择器展示，实际 Minecraft/Fabric 条件在详情兼容版本卡片展示，返回使用 titlebar 全局历史按钮；选择目标或从实例进入均使用相同页面和同一组件。
- 已安装模组管理仍位于实例自己的模组页。全局 `/mods` 首期只发现/安装模组，不把已安装资源仓库、整合包、资源包或光影混入此次改动。
- 列表与项目详情在宽窗口分栏；900px 等较窄窗口使用同页列表/详情切换，返回使用统一 titlebar 历史按钮，恢复原搜索、页码和滚动位置。依赖确认在详情区域内展开，不叠加发现弹窗或第二层安装弹窗。

**未选实例与兼容性**

- 未选实例可搜索和查看项目摘要/来源页面；首期浏览范围明确标为 Fabric，可选 Minecraft 版本。其他加载器尚未实现安装，不展示可用安装操作。
- 查看可安装版本、解析依赖与确认安装前必须选择真实 Fabric 实例。未选实例时详情区提示“选择实例以查看兼容版本并安装”，不拉取不受游戏版本约束的全量版本历史。
- 选择实例后，其安装记录决定游戏版本/加载器筛选；页面不允许覆盖这些兼容条件。实例不存在或不是 Fabric 时显示原因并要求重新选择，不静默回退到另一实例。
- 项目、来源或实例变化时中止旧的页面读取并清空选中文件/安装计划；旧响应不能回写新上下文。搜索/页码可按新的筛选重新读取；先前生成的计划不得用于新目标。

**接口与状态边界**

- 第二项接口约定为鉴权 `GET /resources/{source}/projects`（搜索/可选游戏版本/分页/刷新）和 `GET /resources/{source}/projects/{project}`（公开摘要）；URL 的来源限定 Modrinth/CurseForge，不接受任意上游地址。实际 DTO 与验证范围见下方第二项。
- 全局搜索与现有实例搜索共用提供者查询逻辑和缓存规则；缓存键区分来源、是否指定游戏版本、Fabric、关键词及分页，项目摘要另按项目身份缓存。仍受条目数/体积/TTL 上限约束，不增加后台常驻轮询。
- 目标实例兼容版本和安装计划继续走已实现的实例路由；Runtime 从真实记录校验，前端查询参数不是安装权限或兼容性的依据。计划绑定目标、安装快照与资源 revision，确认前过期/变更即重新生成。
- 复用既有 planId 提交、取消/进度、重复提交保护和结果未知处理；切换页面不取消已确认的安装。取消仍在下载中心显式操作，页面离开只清理自己的读取请求。

第一项仅核对代码并完成以上设计，没有修改界面或 Runtime 行为。第二项当前交付见下方。

### 第二项：全局浏览 API 与缓存（后端实现完成）

- 新增 `GET /resources/{source}/projects`：`source` 限定 `modrinth`/`curseforge`；支持 `q`、`index`、可选 `gameVersion`、`loader=fabric`、`refresh` 和 `after`。省略游戏版本时浏览 Fabric 全局项目，指定时与现有相同条件的实例搜索共用同一个缓存键。非法/空游戏版本、其他加载器、控制字符、超长关键词和越界分页返回 400；不接受未知参数。
- 新增 `GET /resources/{source}/projects/{project}`：读取公开项目摘要，支持 `refresh`/`after`；项目标识使用搜索返回的 Modrinth 8 位 ID 或 CurseForge 正整数 ID。响应 `{ project, stale, revision, freshForMs, refreshError }`，其中项目包含身份、名称、纯文本摘要、作者与来源链接；CurseForge 保留公开 game/class/distribution 字段。摘要不读取文件历史、不返回下载 URL，也不表示已确认对目标实例兼容。
- 搜索继续返回 `{ items, nextIndex, stale, revision, freshForMs, refreshError }`。两种来源均复用既有 Core 提供者、Runtime 来源并发许可、Origin/Bearer 鉴权和请求超时；CurseForge 未配置凭据时返回 503，不访问上游。全局接口不读取实例、不生成计划、不下载或安装文件。
- 搜索/摘要/已有文件列表共用每来源最多 16 个磁盘及内存缓存键和 5 分钟 TTL，不另开无界摘要缓存。指定游戏版本的旧搜索键保持原 JSON 形式，旧磁盘快照可继续读取；未指定版本使用独立键，摘要以查询种类和项目身份隔离。缓存读取验证响应种类、项目 ID、公开字段大小和来源链接，错误快照回退网络；安装版本/计划保持原有实例校验路径。
- 继续使用原始获取时间、首次恢复合并、SWR、手动强制刷新及失败保留规则；Modrinth 仍共用请求间隔及 429 冷却，CurseForge 共用现有有界请求机制。前端 `runtime.ts` 提供 `searchModProjects`/`getModProject` 类型与读取函数，尚未绑定页面。
- 验证：4 项 Core 离线缓存检查和 4 项 Runtime 离线检查通过。覆盖旧键兼容、全局/实例筛选隔离、重建 Context 后恢复原时间、错项目/错种类/外链拒绝、16 项容量上限；真实 loopback HTTP 验证无实例搜索/摘要、鉴权、非法来源/参数、CurseForge 无凭据和既有实例路由仍拒绝缺失实例；受控来源验证并发合并、强制刷新和过期更新失败保留。全部使用临时目录/本地 fixture，没有请求真实平台、下载 JAR、写用户数据或启动游戏。
- Windows Core/CLI 全目标严格 Clippy、Rust 格式与 Svelte 静态检查（0 错误/0 警告）通过。真实 Modrinth 全局搜索/摘要联网联调和 CurseForge 凭据联调仍待进行；不能把离线响应检查写成真实上游验收。

第二项只交付可供后续页面调用的只读 API。第三项当前实现见下方；实例弹窗和安装流程尚未迁移。

## 共享资源目录与文件身份

```text
应用数据目录/
  resources/
    objects/sha256/<前两位>/<完整摘要>   # 无扩展名的受管原件，发布后不原地修改
    records/<资源记录 ID>.json         # 来源、大小、上游哈希、类型等有限元数据
    staging/                          # 尚未完成的下载/发布，复用 q2q-http 恢复能力
  instances/client-<name>/
    instance.json
    installed.json                    # 已有原版游戏安装快照
    resources.json                    # 已提交的资源集合、引用和应用修订
    resource-layout.json              # 已物化受管文件的所有权记录
    resource-transaction.json          # 未完成资源变更的恢复记录
    game/
      mods/                           # 为本实例生成的加载入口
      resourcepacks/                  # 后续，资源包入口
      shaderpacks/                    # 后续，光影入口
      config/ saves/ ...              # 始终为实例私有可写数据
```

- 共享原件放持久数据目录，不放会随普通缓存清理的目录。临时分片可恢复但不是已发布对象；已有原版 `cache/clients/sha1` 不迁移、不混改。
- 对象身份使用完整 SHA-256 + 文件长度。名称、来源项目 ID 或版本号不能单独作为去重键；同名不同内容并存，同内容不同来源共用一个对象并保留各自来源记录。
- 下载前按平台文件身份（平台/项目/版本/文件 ID）和可信预期哈希检索已有对象。跨来源没有可比的可信哈希时，不能保证下载前识别重复；下载后计算 SHA-256 再合并存储。
- 保留上游完整性哈希并按上游声明校验；本地计算的 SHA-256 用于内容寻址，不证明来源可信。本地导入同样计算摘要并标记来源为本地，不冒充平台验证文件。
- 一次解析、下载、记录条目数、单文件大小及并发预算均有界，具体数值在接口实施项确定；共享对象下载按文件身份/摘要加锁，已知相同文件合并在途传输。
- 不推断“同一 mod 的不同版本”可以复用。升级新建对象，旧版本在仍被引用时保留。

`resources.json` 是实例所需资源和启用状态的事实来源，每项至少包含：资源条目 ID、类型、对象摘要/长度、原始来源文件身份、目标安全文件名、项目/版本标识（若有）、enabled、direct/dependency、依赖边与受管状态。引用不保存任意绝对路径或下载凭据。

- `game/mods/` 仍要生成供加载器读取的文件入口，不能只给加载器一份 Anvil JSON。启用条目生成入口；禁用只修改该实例引用并移除受管入口，不改动共享对象或其他实例。
- 设计默认优先使用隔离写入的写时复制（平台/文件系统可用时），否则复制已验证本地原件；均不重复联网下载。共享仓库只保存一个受管原件，但普通复制回退会额外占用实例磁盘，界面不承诺所有平台零重复磁盘占用。
- 软链接作为可选“共享链接”模式：仅连接到受管资源仓库中经验证的普通文件，创建失败回退本地复制并记录实际物化方式；不通过要求用户开启额外系统权限才能安装。
- 默认不使用硬链接：通过入口原地写入会改动共享文件；软链接也存在同样的共享写入风险。只读属性是保护提示，不是对同用户进程的安全隔离。共享链接模式应在应用启动前校验所用对象，损坏时停止并引导修复；不能宣称能阻止运行中的模组修改原件。
- 可能被游戏或模组原地写入的内容必须实例私有；配置、世界、存档、日志、options、运行状态不能链接到全局仓库。
- 只创建/移除清单明确拥有的入口；文件名冲突、内容被外部替换时报告冲突，不覆盖用户文件。发现未知文件时显示“外部添加”，让用户选择导入或保留，不自动删除、上传或默认纳入清理。
- 现有 Core 多处拒绝 symlink；资源模块需为受管链接建立专门验证边界，不放宽实例根目录、世界、已有原版缓存或任意路径校验。

## 加载器、依赖与安装事务

- mod 文件存在不代表能运行：先匹配游戏版本、加载器及其版本、客户端/服务端侧约束；原版实例应先完成显式的加载器安装，不能直接把 mod JAR 塞进原版并标为可用。
- 平台标记只作为匹配依据，不保证所有模组组合能运行。必需依赖自动列入计划，选配依赖由用户决定，不兼容项/循环依赖/无法解析项明确阻止提交或要求选择。
- 为单个实例生成完整变更计划：新增、升级、禁用、移除、间接依赖变化、将复用/下载的文件与预计大小。确认后才开始修改。
- 准备阶段下载/校验并发布共享对象，不改动实例当前可用集合；全部准备成功后获取实例跨进程锁并重新检查配置 revision，防止覆盖其他操作。
- 提交前写恢复日志，记录旧/新清单和受管入口变化；物化到临时位置，在锁内应用入口变更并原子替换 resources.json，最后标记事务完成。不能把多文件更新称为一次文件系统原子操作。
- 中途失败按日志回滚旧集合；崩溃后在下次访问/启动前恢复或明确阻止启动。恢复失败保留证据和旧对象，提供修复入口，不静默当作成功。
- 运行期间不改动实例加载器、资源清单和入口；活动进程身份与实例锁由后续启动生命周期统一管理。首期阻止修改，暂不做“退出后自动应用”的后台队列。
- 单实例资源修改串行；不同实例可并发准备，共享下载复用。逻辑任务各自取消：一个实例取消不能取消另一个实例仍在等待的共享下载，最后一个消费者取消才停止底层传输；消费者集合与任务数量有界。
- 资源任务复用窗口级下载任务展示，任务语义使用独立种类，不假设现有原版安装 API 已支持资源操作。暂停/继续的具体 Core 集成需在实施阶段设计，不能把当前原版任务实现直接宣称为已支持。

## 删除、升级与清理

- 从实例移除 mod：只改该实例清单与受管入口。先展示必需依赖与被依赖者，阻止留下缺失必需依赖的集合；可选清理没有其他用途的间接依赖。
- 删除实例：停止/阻止活动任务与运行进程后处理实例私有数据及引用；是否同时删除世界必须另做明确确认。共享原件不随实例删除。
- 全局资源删除：列出全部引用实例；仍被引用的对象不得直接删除，必须先逐实例移除/替换。升级只影响显式选定实例，不全局替换旧文件。
- 首版仅手动“清理未使用资源”，展示可回收空间后确认；不后台自动 GC。引用以持久清单为准，反向索引可重建，不依赖容易漂移的单一计数器。
- 清理排除实例当前清单、未完成事务旧/新集合、安装任务租约和运行会话引用；与下载发布/事务提交使用共同锁协议。实例清单损坏或扫描不完整时不删除候选。
- 对象损坏后按可信来源显式修复；本地导入且无法重新获得的文件保留记录并要求用户重新选择，不能以“缓存可重建”为由删除。

## 执行项 2：本地资源与实例引用

### 已实现范围

Core 新增 resources 模块，ResourceManager 提供读取清单、本地 JAR 导入、启用偏好和移除引用。共享原件路径为 data/resources/objects/sha256/<前两位>/<完整摘要>，实例清单为 instances/<id>/resources.json。按内容摘要复用；发布已有原件时检查普通文件、大小与完整哈希，损坏时明确拒绝，不静默重用或覆盖。相同内容再次导入同一实例为幂等操作，不重置原有启用状态；不同内容重名（忽略 ASCII 大小写）拒绝。

当前 schema 1 是仅用于本地模组的最小清单：schemaVersion、revision、mods[]；条目含 source=local、sha256、filename、size、enabled。mods 数组隐含类型为 mod，本地导入均为直接引用；平台身份、依赖图和自动求解暂未实现，后续扩展需迁移 schema，不假装已具备这些元数据。

启用仅保存“计划启用”的实例偏好，导入默认停用；本阶段不写 game/mods、不建立软/硬链接，也不复制游戏入口。理由：加载器尚未接入，现阶段不把管理成功显示为加载成功。软链接/写时复制/复制策略和多文件事务恢复仍归执行项 3 的入口物化；不宣称本项完成了实际 mod 启动或通用资源事务。

### 原子性与限制

- 资源操作复用 Core 两个 blocking permit 和跨进程实例锁；导入发布共享对象时另持有资源仓库锁。提交验证前端携带的 revision，禁止旧清单覆盖新修改；revision 限制在 JS 安全整数范围。
- 完整对象先以同目录临时文件写入、sync 后无覆盖发布，再通过既有 replace_json 原子替换清单。没有多文件游戏入口变化，因此无需多文件恢复日志。失败/中断发生在引用提交前时旧清单保留，可能留下无引用共享原件，暂不自动删除。移除仅删除当前实例条目，共享原件始终保留。
- 单文件 1 字节–64 MiB、最多 4096 个 ZIP 条目，不支持 ZIP64；先检查目录计数再解析 ZIP，不解压或执行。只确认 JAR/ZIP 格式，不识别模组兼容性、依赖或恶意代码。
- 单实例最多 1024 个受管引用、清单最多 1 MiB；文件名最多 128 字节、以 ASCII 字母/数字开头、允许字母数字与空格及 . _ + -，要求 .jar 后缀，拒绝路径与设备保留名。导入不接受任意服务器文件路径，只接收显式选择文件的内容。
- 此阶段不扫描、覆盖、删除用户 game/mods 外部文件；没有全局清理入口，不能以零引用自动删资源。运行/原版安装占用既有实例锁时拒绝资源访问。

### Runtime 与页面

鉴权 API：GET/POST /clients/{name}/resources，POST 使用二进制请求体与 filename/revision 查询参数；DELETE /clients/{name}/resources/{sha256}?revision=...；POST /clients/{name}/resources/{sha256}/enabled 使用 revision/enabled JSON。资源路由在读取请求体前只准许一个在途请求，上传体最多 64 MiB，普通 API 保持原有 64 KiB 限制。日志只记录动作、稳定错误类别、清单修订和条目数量，不记录文件名、内容或实例身份。

实例模组页提供本地选择/确认导入、清单/名称搜索/文件身份、计划启用/停用、移除确认与手动刷新。关闭或切换路由中止前端请求；已被服务端接受的变更可能继续完成，不等同取消任务。操作响应未确认时保留旧清单并禁止继续变更，用户显式刷新确认结果；刷新失败保留已读取列表。页面明确说明加载器未接入，计划启用不代表当前游戏会加载。

### 下载、去重与事务

Core 分为 resources/platform（计划、来源/依赖与实例提交）、resources/transfer（共享原件与 q2q-http 传输）、resources/transaction（原有物化/恢复）；Runtime 任务独立放 resource_operations，不把生命周期塞回 API 路由文件。

- `data/resources/sha1/<上游摘要>.json` 是内容索引，保存 SHA-256/长度；复用前校验原件 SHA-256、上游 SHA-1、大小及受支持 JAR 格式，不仅相信索引。损坏/不一致明确失败，不覆盖共享原件。
- 缺失文件通过原有 Context 的 q2q-http 下载到 `resources/staging/sha1/<摘要>`，使用上游 SHA-1/预期大小及 q2q 的恢复日志；不另写 Range、分片或恢复格式。只接受先前验证的无凭据/无查询参数官方 CDN HTTPS URL；下载不携带 API Key。每文件 1–64 MiB，每计划最多 32 个项目，顺序准备，共用原有全局并发预算。
- 每摘要使用进程内锁与跨进程文件锁，避免同时写同一 staging。其他进程占用返回 Busy；此阶段不声称实现多个实例同时消费同一底层传输。一个 Runtime 只接受一个资源安装任务；其他原版安装仍使用各自生命周期与共同 Context 下载预算。
- 下载完成再次有界读取，校验上游 SHA-1/JAR，计算 SHA-256；持有仓库锁无覆盖发布原件并原子写索引，成功后移除 staging 成品。已有原件按摘要复用；本地导入没有上游索引时，不保证首次平台下载前识别相同内容，下载后仍合并原件。
- 准备期间不修改实例资源集合。所有文件完成后，取得原有实例/资源仓库锁，重新检查完整旧清单、游戏版本与 loader，再通过单个既有事务提交全部启用引用及 mods 私有副本。下载失败、提交前取消或修订冲突保留旧集合，已准备共享原件留待复用。
- 提交阶段取消按既有事务尝试回滚；提交点已成功则完成优先。提交后清理失败可能已改变集合，任务提示刷新确认结果，前端对完成/失败/取消均刷新清单，不自动重试变更。恢复失败仍保留 journal/backup 并阻止后续操作。

### 第 1 项：确认的实施设计

#### 产品行为

- 首期支持显式选择本地 ZIP。导入后进入当前实例的资源包目录，玩家在 Minecraft 的“选项 → 资源包”选择与排序。
- 界面使用“已添加到实例”，不沿用模组的 enabled 开关；导入成功不等于游戏内已启用。首期不改写 options.txt，不自动调整资源包顺序或启用列表。
- 移除只撤销当前实例引用及其受管副本，保留共享原件；不修改世界、模组、游戏配置或非受管文件。不提供自动清理共享原件。
- 原版与 Fabric 实例都可添加资源包，不依赖 Fabric/Iris；光影 ZIP 的识别、加载器与 shaderpacks 规则留待单独设计。

#### Core 与存储

- 继续使用 data/resources/objects/sha256/<前两位>/<摘要>，相同 ZIP 内容跨实例复用一个共享原件；实例以引用记录资源包身份。运行目录使用独立副本，避免游戏/外部工具修改共享原件。
- 保留现有 ResourceEntry 模组契约及 CurseForge origin，资源包使用独立的 pack 条目（摘要、安全文件名、大小、本地来源及解析的格式信息），不强塞模组依赖与 enabled 语义。
- resources.json 下一版 schema 3 增加 resourcePacks 集合；读取 schema 1/2 时按空集合兼容，读取不自动写盘，首次成功变更升级。模组变更必须保留资源包集合，资源包变更必须保留模组集合，沿用同一 revision 防止互相覆盖。
- resources.rs 继续负责仓库/引用入口；新增 resources/packs.rs 负责 ZIP 与包元数据校验。先抽取实际复用的对象发布、目录/文件校验，避免复制整套 mod manager。
- resource-layout.json 与恢复事务扩展为按资源类型记录受管入口；旧 journal 按旧结构恢复完成后才允许新事务。game/mods 与 game/resourcepacks 各自有固定目标，不接受前端指定相对或绝对路径。事务实现按类型选目标目录，复用现有准备/备份/提交/恢复规则。

#### 文件与元数据边界

- 初版沿用上传上限 64 MiB、每实例最多 1024 条资源引用及有界 JSON；ZIP 最多 4096 项。首期不支持目录导入、远程 URL 或 ZIP64；超限明确提示，不静默截断。
- 必须为可读取的 ZIP，根目录存在唯一 pack.mcmeta，单份解压后最多 256 KiB；有界读取并校验 JSON 与 pack 对象，拒绝根元数据重复、损坏及嵌套目录伪装的包。
- 不解压整个 ZIP、不执行其中内容、不自动转换包格式；共享对象按原 ZIP 的完整摘要保存。校验容器路径，拒绝绝对路径、父目录穿越及符号链接条目。
- pack_format 及新格式范围的具体字段校验在第 2 项按实际官方格式补齐，不能只接受某一旧整数格式而错误拒绝新版包。缺少游戏版本对应关系时标为“兼容性未确认”，不凭文件名宣称兼容。
- 描述可能为文本或 Minecraft 文本组件；只提取有界纯文本用于展示，不渲染 HTML、不加载描述中的链接/外部资源。封面图片读取先不纳入首期，避免把图片解码与 ZIP 导入耦合。

#### 并发与失败

- 复用实例运行锁、共享仓库锁及修订检查。游戏运行/安装占用实例时拒绝资源包变更；不承诺热添加/热移除立即生效。
- 同内容重复导入幂等；同类型不同内容同名（忽略 ASCII 大小写）拒绝。没有所有权记录的同名 ZIP 不覆盖、不收编；受管副本被外部修改时保留冲突，禁止直接删除。
- 对象准备不改变实例；实例引用和受管副本通过恢复事务提交。失败时保留旧集合，恢复未完成则阻止后续变更，不把残留共享对象当成已导入成功。
- 变更响应不明时前端保留旧列表并要求刷新确认，不能自动重发上传或移除。读取错误不能变成空列表。

## Fabric 启动类路径后缀修复

维护者真实启动反馈 Tiny Remapper 生成结果无类。只读检查被报告的客户端缓存 ZIP，内含 10291 个 class；启动时把无后缀 SHA-1 blob 直接传入了类路径。[Tiny Remapper 官方源码](https://github.com/FabricMC/tiny-remapper/blob/master/src/main/java/net/fabricmc/tinyremapper/TinyRemapper.java) 在扫描输入时只接收 .jar/.zip/.class 后缀，与该故障相符。

Core 新增 client/classpath.rs：Fabric 启动前在既有临时 session/classpath 下生成 <sha1>.jar 视图，包含客户端与所有类路径库；不修改下载缓存或安装清单，不重新下载。相同摘要在同一次会话只复制一份，采用独立文件以隔离 Loader 写入，复制有长度上限、取消检查与 SHA-1 复核。临时视图可能增加单次启动的磁盘 I/O 与临时空间，用现有 RuntimePreparation/LaunchSpec 生命周期持有，正常退出、取消或准备失败时随 session 回收。原版继续使用原有路径。

launch.rs 保留安装记录/计划身份校验，Fabric 的 classpath 改为已准备的 .jar 路径；日志配置等非类路径文件仍使用原有解析。未删除用户的 .fabric 缓存或更改实例资源。检查：Rust 格式、Core/CLI 严格 Clippy、macOS ARM64 release 构建并更新开发 baseline；未添加/运行测试、未启动真实游戏或重启 dev。实际修复结果需维护者重启 dev 后重新启动确认，不能把源码诊断与编译通过写成游戏成功。
