# AI 玩家

状态为本地同步执行器原型与二维策略实验已实现。本文定义下一阶段的目标架构，真实游戏适配、目标条件策略和 LLM 主脑尚未接入。首个 Minecraft 版本、Azalea 固定版本及工具链方案待确定。

## 产品目标

AI 玩家能理解其他玩家的请求，一起行动，并根据真实进展交流。LLM 主脑决定方向与合作承诺，实时层持续完成当前目标，及时处理环境变化；主脑推理期间，实时执行继续运行。

首个完整场景是「跟着 Leo 去村庄」。主脑建立跟随目标，实时层维持合适距离、绕过障碍、让路及避险；目标暂时不可见时，根据最后已知位置和有界搜索尝试恢复。持续无法恢复时报告阻塞，由主脑决定询问、等待或改变计划。持续跟随任务不会因短暂靠近而完成，到达村庄必须有独立的可验证判据，或者由玩家明确结束。

## 分层与信息流

| 部分 | 职责 | 边界 |
| --- | --- | --- |
| LLM Agent Runtime | 理解对话、协商目标、安排长期计划，维护玩家偏好和承诺 | 输出结构化目标，通过已确认事实描述进展 |
| 实时策略 | 根据当前目标、最新观察、近期历史和空间记忆，选择短时动作或技能 | 独立闭环，能够持续跟随、搜索、等待和避险 |
| 执行器 | 管理目标修订、动作归属、权限、抢占、取消、期限和回执 | 所有动作统一经过检查，同一控制通道只有一个有效拥有者 |
| 游戏适配器 | 采集游戏状态，将动作映射到游戏操作并确认结果 | 明确协议能力、可观察范围及未知信息 |
| 共同状态与记忆 | 保存任务进展、事实、目标最后位置、已探索区域和合作承诺 | 有界、带来源和时间，区分事实、推断与过期数据 |

首批采用协议级 Bot 路线，优先验证 Azalea。服务端 Mod 保留为另一适配器，复用上层目标与动作语义，分别声明权限和可观察能力。协议可获得的信息不自动等于玩家实际可见的信息，训练和运行必须采用一致的观察约束。

## 主脑与实时层的契约

### 目标

主脑提交的目标至少包含以下信息。

- `goal_id`、修订号、会话和发布时刻，用于识别目标与过期决策。
- 目标类型和参数，例如跟随某玩家、前往已知位置、收集指定数量物品或等待。
- 约束，例如允许破坏的方块、活动范围、物品使用权限、合作距离和风险预算。
- 完成条件、阻塞判据及有效期限。持续任务与有限任务分别定义终止方式。
- 任务来源、关联玩家和前置条件。模型只能在已支持的能力与权限中选择。

首期用类型化字段连接两层，文字可作为解释。任意新文字指令不能直接变成未经训练的技能。目标通过校验后才生效；替换正在执行的目标时，先完成必要取消与控制权交接。

目标状态统一为待接受、执行中、暂停、阻塞、完成、失败或取消。临时避险记录为执行子状态，原目标继续保留；危险解除后检查目标有效性和环境条件，再恢复或报告阻塞。

### 观察与策略输出

策略输入为当前目标与修订、带新鲜度的局部观察、近期动作及其确认结果、相关空间记忆和当前执行状态。未知、未加载和已过期信息显式表达。环境记忆包含最后见到玩家或资源的位置、时间和探索记录，不能只依赖短历史窗口。

策略输出包含动作类型、目标对象或位置、有限参数、建议持续时间，以及对应观察序号和目标修订。模型可以选择等待、重新观察、局部搜索或请求主脑帮助；完成与失败由可核对条件判定。

首期动作粒度优先采用短时、可中断的技能，例如向路点移动、保持距离、查看方向、等待和交互。寻路和游戏物理能力尽量复用适配器已有实现。具体粒度在真实接入后验证，避免长时间动作屏蔽策略反馈，也避免在缺少操作数据时直接学习逐 tick 键鼠控制。

### 反馈与调度

- 常规进度写入共同状态并合并摘要。阻塞、目标丢失、危险变化、玩家新请求和任务终止按重要性触发主脑。
- 主脑异步读取状态快照，返回结果携带所依据的会话和目标修订。推理期间目标已变化时，拒绝或重新核对旧结果。
- 实时层不断读取最新观察。推理任务采用有界队列和最新快照合并，丢弃过期建议，避免积压历史决策。
- 玩家停止、断线、过期观察及越权操作由执行器直接处理。停止取消当前控制，不等待 LLM 或策略推理完成；取消确认前不得发布冲突动作。
- 主脑超时或不可用时，实时层仅在目标有效期、权限与风险范围内继续；条件不满足则暂停并报告。恢复连接不自动重新执行已取消目标。

采样率、策略决策频率、动作期限和停止延迟预算在真实适配阶段测量后确定。游戏 tick、观测频率、模型推理频率与控制输出频率分别记录。

## 模型与训练方案

学习目标为目标条件策略，覆盖持续执行、恢复与短时反应。XGBoost 保留为候选动作排序基线，序列模型用于比较近期动作、环境变化与目标条件建模能力。最终采用哪个模型，以真实游戏闭环表现和部署成本决定。

1. 建立规则或已有导航能力支持的可运行基线，用于真实接入验证与采集初始示范。
2. 记录目标、当时可用观察、相关记忆、执行状态、实际动作、耗时和回执，用行为克隆学习可执行行为。标签明确来自规则专家、人工操作还是人工纠正。
3. 加入目标暂时消失、搜索失败、危险打断、目标替换、过期指令与恢复等轨迹，训练时模拟主脑延迟和不同步观测。
4. 闭环收集模型造成的偏离和失败，再补充纠正示范。未实际执行动作的后果保持未知，不用固定专家续跑分数冒充真实最优动作。
5. 行为克隆达到基线后，再评估强化学习或结果排序改进；允许在可重置模拟环境生成补充数据，真实与模拟结果分别统计。

按世界、地图、玩家轨迹和完整 episode 隔离训练、验证与盲测。记录成功率、损伤和死亡、停止响应、恢复率、搜索耗时、动作切换、玩家干预次数，以及推理耗时和资源占用。平均推理耗时之外记录尾延迟与超期次数。

## 代码组织

- `crates/anvil-agent` 承载与游戏 SDK 无关的目标状态、执行器和策略接口。已有确定性技能作为基线，接口按真实接入逐步调整。
- Azalea 连接、世界观察与操作映射放入适配边界。固定 SDK 和工具链后再决定独立 crate 与进程位置，保持依赖和运行时归属清楚。
- `experiments/` 继续平铺实验目录，使用 uv 和 Python 3.13，保存数据处理、训练和评估代码。新增模型只在存在实际实验时建目录。
- LLM Runtime 通过目标与反馈接口接入，共享任务状态，不能直接绕过执行器操作游戏。

## 当前实现与差距

- `crates/anvil-agent` 已有模拟事件驱动的同步执行器，覆盖跟随、避险抢占、停止、故障边界和数量型采集。它尚未实现本文完整目标契约、真实观察和学习策略接入。
- `experiments/` 已有二维模拟环境、轨迹生成、XGBoost 与小型 Transformer 训练、回放和闭环评估。结果见[实验说明](../experiments/README.md)与[评估记录](../experiments/evaluation/README.md)。
- 现有二维候选排序实验保留为回归材料。其有限窗口评分、二维动作与简单环境不足以验收真实游戏中的目标条件策略或长期合作能力。
- 真实游戏连接、空间记忆、真实示范数据、LLM 主脑和自然合作均待实现。

## 执行项

按顺序逐项推进，每项完成后说明验收结果及下一项范围，再由维护者确认继续。

### 1. 固定首个场景与目标契约

- [x] 以跟随玩家为首个纵向场景，确定目标字段、状态转换、反馈事件和适配器能力声明。
- [x] 明确跟随、短暂丢失、搜索、阻塞、避险、恢复及停止的边界与完成条件。
- [x] 确定数据与决策中的会话、目标修订、观察序号和动作 ID 对应关系。

契约见[持续跟随目标契约](../docs/ai-player/follow-contract.md)。已新增独立契约模块及 5 项人工时钟事件序列测试，覆盖主脑延迟、目标替换、过期输出、阶段切换和停止取消；连同既有 9 项原型测试共 14 项离线测试通过，格式检查通过。尚未与旧 Executor 合并，不调度真实动作；搜索预算、危险判断、反馈传输和生命周期定时器留待后续接入。

### 2. 确定真实游戏基线并接入

- [ ] 固定 Minecraft Java、Azalea 和 Rust 工具链，确认 workspace 兼容性及适配器位置。
- [ ] 在隔离测试服验证入服、出生、断线、重生及跨维度事件。
- [ ] 接通位置、实体、局部地形与聊天观察，以及移动、寻路、注视、等待和停止回执。
- [ ] 用确定性基线完成跟随与停止，测量观察和操作时序，再确定实时预算。

实施顺序如下，当前仅记录计划，尚未开始第 2 项。

1. 核对 Azalea 的 Minecraft 支持范围、Rust nightly 和依赖要求，固定版本及提交。必要时隔离构建入口，具体 crate 位置以兼容性检查结果为准。
2. 建立独立开发运行入口，明确认证配置、连接及退出流程，在隔离测试服验证出生、断线、重生和维度切换。会话变化必须使旧观察、决策和回执失效。
3. 接入自身位置、附近玩家和导航所需地形，复用 Azalea 寻路；映射移动、注视、等待、完成、失败及停止确认。将新契约与旧 Executor 整合成单一控制入口，避免双重控制。
4. 运行确定性跟随基线，验收距离保持、改变方向、障碍导航、目标消失后的停止与报告，以及移动中停止。记录观察间隔、导航响应和停止延迟，再确定实时预算。

验收产物为固定版本、可复现命令、适配能力表和真实跟随记录。停止后旧动作与旧会话回执不能恢复移动。有界搜索、空间记忆和完整避险恢复仍属于第 3 项；真实游戏验收需要维护者参与，版本或认证阻塞应先说明具体证据再确认。

### 3. 接入空间记忆和恢复闭环

- [ ] 保存带时间和来源的最后可见位置及有界探索记录，处理区块未知和世界切换。
- [ ] 实现有期限的局部搜索、受阻反馈、临时避险和恢复检查。
- [ ] 以规则基线跑通目标丢失、路径受阻、危险打断和取消竞争场景。

验收区分短暂丢失后的恢复与持续丢失后的阻塞，避免无限搜索和反复切换。

### 4. 采集真实示范并训练策略

- [ ] 固定轨迹 schema、动作粒度、数据版本、回放和 episode 划分。
- [ ] 收集正常执行、恢复、失败和人工纠正轨迹，检查观测与动作时序。
- [ ] 训练目标条件行为克隆基线，比较 XGBoost 与适合序列输入的模型。
- [ ] 从旁路建议进入隔离测试服闭环，按同一场景评估基线与模型，补充失败数据。

验收以独立地图的真实闭环结果和资源预算决定模型采用，不以模拟排名或离线准确率替代。

### 5. 接入异步 LLM 主脑

- [ ] 将玩家请求转换为受支持的结构化目标，确认接受后写入共同任务状态。
- [ ] 接入合并进度、关键事件和状态摘要，支持目标修改、暂停与取消。
- [ ] 注入慢响应、超时、失败和乱序返回，验证实时行为持续运行且旧结果失效。
- [ ] 对话使用已确认事实，记录和履行玩家承诺。

验收包含「跟着我」「等我一下」「继续走」与「别跟了」。阻塞时主脑可以询问和改计划，停止始终即时进入取消流程。

### 6. 扩展采集与自然合作

- [ ] 逐步加入挖掘、拾取、快捷栏、交付及背包结果确认，每种能力明确权限与训练覆盖。
- [ ] 扩展目标条件数据与闭环评估，检查新任务是否损害跟随、停止和避险。
- [ ] 加入按玩家区分的对话、偏好、共同经历、社交距离、让路及提示时机。
- [ ] 验收「陪我去挖矿」「把木头给我」及多人目标冲突，结合任务指标和玩家评价检查自然度。

## 设计依据

- [JARVIS-1](https://arxiv.org/abs/2311.05997) 与 [STEVE-1](https://arxiv.org/abs/2306.00937) 提供语言规划与学习控制器分层的 Minecraft 先例。
- [Helix](https://www.figure.ai/news/helix) 展示异步双模型和训练时模拟两层时序差的方案。其联合训练隐向量接口作为参考，当前计划采用结构化目标接口。
- [MrSteve](https://sites.google.com/view/mr-steve/home) 提供独立空间事件记忆、探索与学习导航器的参考。
- [Real-Time Chunking](https://www.pi.website/research/real_time_chunking) 提供异步推理与动作衔接的参考，具体连续动作生成算法不直接套用于当前离散技能。

这些工作支持分层设计方向，不能替代 Anvil 的真实数据与实时验收。论文中的视觉键鼠控制、机器人动作及模型规模与当前协议级适配不同。
