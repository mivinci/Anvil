# 原版客户端首条可用流程

状态：执行方案；客户端文件安装、账户授权和启动尚未实现。`anvil version list` 已能读取并校验 Mojang 版本总清单中的条目，但不会获取版本 JSON 或下载游戏文件。

## 目标

逐步打通原版客户端的版本选择、文件安装、账户授权和启动。CLI 与 GUI 共用 `anvil-core` 的元数据、安装和启动逻辑；下载继续复用固定 revision 的 `q2q-http`，不另造下载与恢复机制。

首个客户端版本建议从资料已核对的 1.21.1 开始。开始实现前先确认 OS/CPU 支持矩阵；版本及平台没有真实验收前，不宣称可运行。26.3 包含尚未实现的 `default-user-jvm`、`os.versionRange` 等规则，先不纳入首批支持范围。

## 执行项

### 1. 收敛当前 PR 反馈与基础约定

**交付：** README 面向启动器用户描述用途和当前能力；Core 测试文件直接放在 `crates/anvil-core/tests/`，不再按 `unit/` 子目录分层；生产路径不以 `unwrap` 处理可恢复错误，按需接入 `tracing` 记录诊断，并避免记录令牌、完整启动参数等敏感信息。

**验收：** 对应 PR 评审意见已处理；格式、测试、Clippy 与桌面入口 CI 通过；测试 fixture 的断言仍能给出具体失败原因。

### 2. 确定首批客户端支持矩阵与安装契约

**交付：** 确认首个游戏版本及 Windows、macOS、Linux 的目标 CPU 架构；定义客户端实例 ID、数据目录、安装记录和 CLI 命令。初步命令形态为：

```bash
anvil client install <name> --version <id>
anvil client list --json
anvil client launch <name>
```

**验收：** 文档明确每个命令的副作用、可重试行为、实例与共享缓存边界；没有选定或未验证的平台不会被隐式视为受支持。

### 3. 解析并校验客户端版本 JSON

**交付：** 从已验证的版本总清单选择版本 JSON，按原始响应字节校验清单中的 SHA-1，再解析版本 ID、Java 要求、客户端 JAR、资源索引、主类和参数字段。复用有大小上限的共享 HTTP Executor；不信任未经校验的来源 URL。

**验收：** fixture 覆盖成功解析、哈希不符、版本 ID 不符、缺少客户端 JAR/Java 要求、无效 URL/长度/哈希和超限响应；不访问真实 Mojang 网络。

### 4. 生成平台相关的客户端安装计划

**交付：** 按目标 OS/架构及 Mojang rules 选择 libraries、classifiers、native JAR、assets 和日志配置。将旧式 natives 解包与现代 native JAR 区分处理；对未知规则和不支持的旧版资源布局明确返回 unsupported，不默认放行。

**验收：** 固定官方样本覆盖规则 allow/disallow、平台与架构选择、提取排除路径、资产哈希去重、缺失字段和不支持条件；计划只包含当前目标平台需要的文件。

### 5. 安装文件并原子提交客户端实例

**交付：** 所有已知大小与可信哈希的文件交给共享 `q2q-http` 下载、并发、校验和恢复；无大小元数据使用有界读取。缓存存放可校验的不可变内容，实例安装在 staging 中完成后再原子发布 `installed.json`。取消或失败时清理由该操作拥有的临时数据。

**验收：** fixture 覆盖缓存复用、损坏缓存修复、哈希/长度错误、并发安装、取消清理和失败重试；半成品不被列为已安装，CI 不下载真实游戏文件。

### 6. 准备 Java、assets 与 natives 运行目录

**交付：** 复用现有托管 Java 管理器，按版本要求选择或安装匹配运行时；检查 assets 索引及对象完整性；将运行时可能写入的 natives 解包到会话隔离目录，不修改共享缓存。

**验收：** fixture 覆盖 Java 版本/架构不匹配、对象缓存校验、解包路径安全、并发会话目录隔离和清理；缺少目标平台运行时来源时明确失败。

### 7. 完成账户授权与客户端启动参数

**交付：** 单独设计微软/Xbox/Minecraft 授权与系统凭证库保存、刷新和撤销流程；生成结构化 `LaunchSpec`，将 JVM 参数、main class 和游戏参数作为独立 argv 元素传递。完整 token、授权响应和敏感参数不得写入日志或 JSON。

**验收：** 账户服务使用替身测试，真实登录由维护者交互验收；参数 fixture 覆盖现代数组和纳入支持范围的旧格式、rules、占位符、路径含空格、Java 选择、日志参数及缺失账户。不得伪造 `clientid`、token 或以离线身份冒充正版登录。

### 8. 接入 CLI 与可选桌面流程

**交付：** CLI 先提供安装、列表、登录和前台启动；`--json` 输出 schema 版本化结果，长任务有明确进度、取消、退出码和清理语义。随后 GUI 调用相同 Core API，不通过 CLI 子进程实现常规业务。

**验收：** CLI 集成测试覆盖 JSON 纯净输出、取消、错误码、重复操作和子进程日志；GUI 检查不改变 Core 结果。各 OS/CPU 的真实安装与启动通过本地 smoke 脚本逐一记录，不加入 Live CI。

## 首批不包含

Fabric、Forge、NeoForge、整合包、账号共享/云同步、后台启动、MCP、自动迁移旧启动器数据和自动更新。每项需要独立的数据与生命周期方案。
