# 桌面国际化维护

Desktop 当前实现简体中文（`zh-CN`）和英文（`en`）。语言入口位于设置 → 通用；已保存选择优先，其次按系统语言列表匹配，无法匹配时回退简体中文。恢复“跟随系统”会移除本机 `anvil.locale` 偏好。切换即时更新页面和 `document.lang`，不重载业务流程；存储失败时保留当前窗口选择并提示。

自动化检查已覆盖双语页面与布局；macOS、Windows 原生 WebView 的首帧、持久化和布局仍待手测。实际验收记录见[执行清单](../todos/desktop-i18n.md)，命令与 fixture 边界见[测试说明](../apps/desktop/tests/README.md)。

## 实现位置

| 位置 | 职责 |
| --- | --- |
| `apps/desktop/src/lib/i18n/zh-CN/`、`en/` | 按 common、nav、home、clients、instance、mods、settings、account、errors、welcome 分域的词典 |
| `apps/desktop/src/lib/i18n/index.ts` | 语言列表、语言名称、默认语言、匹配规则与词典入口 |
| `apps/desktop/src/lib/locale.svelte.ts` | 窗口语言状态、偏好持久化与存储失败提示 |
| `apps/desktop/static/locale-bootstrap.js`、`src/app.html` | hydration 前设置语言，显示静态双语启动提示 |
| `apps/desktop/src/lib/i18n/format.ts` | 显式接收 locale 的 Intl 格式化 |
| `apps/desktop/src/lib/runtime-errors.ts` | Runtime 稳定错误码到页面文案的映射 |
| `apps/shell/bootstrap/` | 独立的 Shell 恢复页，仅按系统语言选择，不读取 Desktop 偏好 |

## 修改文案

先在 zh-CN 对应域定义语义明确的键，再同步 en。源语言导出 `Messages`，英文入口和子域通过类型检查约束结构。组件从 `localeState.messages` 读取文案，不能在模块初始化时缓存已翻译的句子；保存错误码、阶段或 issue，渲染时再翻译，已有错误才能随语言切换。

完整句子由词典函数插值，不在组件拼接词序。数量按目标语言处理单复数；日期、数量和文件大小显式使用窗口 locale，保留原有 KB/MB 与 KiB/MiB 的单位语义。可见文字、页面标题、aria-label、title、placeholder、alt 和 sr-only 同样需要翻译。语言名称使用自身语言并标注 lang。

账户名、实例名、文件名、版本、验证码、第三方项目介绍、官方新闻与游戏日志保留原文。Anvil 内置编辑内容提供双语。产品名 Anvil、Minecraft、Fabric、Iris、Sodium、Modrinth、CurseForge 保留拼写。

Runtime 保留原始 `error`/原因，并通过 `code`、`errorCode`、`reasonCode` 或 `warningDetails` 提供语义；页面按码翻译，原文放在可展开的技术详情。未知码使用通用提示，旧 Runtime 缺码时使用上下文回退，不能从诊断句子猜测含义。翻译不能改变未知提交结果的只读核对和原计划重试规则。CLI 与 tracing 不在此翻译范围内。

## 术语

| 中文 | 英文 | 使用范围 |
| --- | --- | --- |
| 实例 | Instance | 用户独立管理的游戏环境；客户端库标题可用 Clients |
| 模组 | Mod | Mod 文件和在线项目 |
| 资源包 | Resource pack | 游戏材质等资源包，不使用 texture pack 泛指 |
| 光影 | Shader / Shader pack | 导航使用 Shaders，具体文件称 shader pack |
| 整合包 | Modpack | `.mrpack` 导入与导出 |
| 加载器 | Loader | Fabric 等加载器 |
| 安装版本 | Install version | 游戏安装入口 |
| 导入 / 导出 | Import / Export | 本地文件操作 |
| 移除 / 删除实例 | Remove / Delete instance | 移除资源引用与删除整个实例使用不同动词 |
| 下载任务 | Tasks | 全局任务面板，包含准备与安装阶段 |
| 技术详情 | Technical details | 保留原始诊断的展开区域 |
| 跟随系统 | System default | 语言偏好选项 |
| 启动 / 运行中 | Launch / Running | 游戏动作与状态；首页主动作可使用 Play |

术语按语境组织完整句子，不把该表当作机械替换规则。

## 新增语言

1. 从源词典建立新语言目录与入口，完整实现 `Messages`，包含函数参数、数量形式和无障碍文案。请目标语言使用者审校，不只检查键存在。
2. 在 `i18n/index.ts` 更新 `locales`、`Locale` 推导、`localeNames`、`messages`、`isLocale` 和 `resolveLocale`。默认语言保持现有约定，除非另行确认。检查设置选项和 LocaleState 的类型与持久化测试。
3. 同步首帧 `static/locale-bootstrap.js` 的匹配规则，以及 `src/app.html` 的启动 span 和语言显示 CSS。守卫要求每个语言的启动文字与 `common.loading` 完全一致。不要添加内联脚本或放宽 CSP。
4. 扩展 `scripts/check-desktop-i18n.mjs` 对新词典的结构比较，并检查语言范围写死的位置：`tests/i18n.test.ts`、`locale-state.test.mjs`、`settings-language.browser.mjs` 和 `mod-discovery.browser.mjs`。修改 bootstrap 与应用规则一致性测试，覆盖语言变体、顺序、无效偏好和回退。当前守卫入口与综合脚本仅支持 zh-CN/en，需要显式扩展。
5. Shell 恢复页有独立语言集合。若同时支持新语言，更新其静态正文、CSS、`__anvil_shell__/recovery.js` 与 Shell 恢复测试；继续只按系统语言选择，并保留无 JavaScript 的可读回退。不要让 Shell 读取 App 存储。
6. 运行下述检查和新语言浏览器回归；检查最小 620px 与宽窗口、长文件名、任务失败、确认按钮及键盘焦点。最后在目标平台原生 WebView 验收首帧、即时切换和重启持久化，分别记录未完成的平台。

## 检查

仓库根目录执行：

```sh
npm run desktop:i18n-check
npm run desktop:check
npm run build --workspace @anvil/desktop
```

守卫检查词典键、类型、数组长度和函数参数数量，扫描 Desktop src 词典目录之外的汉字。静态启动文字严格对照词典，不豁免整个 HTML；当前没有其他允许列表。它不能判断英文是否准确，也不能代替人工阅读与原生 WebView 验收。

Node 测试及双语浏览器命令统一维护在[测试说明](../apps/desktop/tests/README.md)。浏览器使用本地 fixture，不能将其成功登记为真实账户、下载、游戏加载或原生平台通过。
